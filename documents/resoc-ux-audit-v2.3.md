# Ресоциализация: аудит и брифинг трёх AI-экспертов

Дата: 6 сентября 2026 года. Исходная версия: 2.2. Доработка: 2.3.

## Как проводилась работа

Три независимых AI-эксперта изучили исходники и данные, подготовили замечания, обсудили общий бриф и повторно проверили внесённые изменения. Это не рецензии приглашённых людей и не пользовательское исследование.

| Эксперт | Область ответственности | Основной вывод |
|---|---|---|
| UX и пользовательские сценарии | Поиск → подбор → сравнение → консультация | Нужно сохранять контекст выбора, показывать полную выдачу и честно объяснять ограничения каталога. |
| Визуальный дизайн | Сетка, типографика, адаптация, состояния | Качество повышают устойчивые размеры и ясная иерархия; существующая тёмная навигация и синий акцент подходят рабочему сервису. |
| Доступность и надёжность | Фокус, диалоги, уведомления, асинхронные запросы | Перерисовка не должна терять фокус; уведомления должны оставаться в активном диалоге, состояния сети — различаться. |

## Согласованный бриф

1. Сохранить рабочую структуру каталога и единую визуальную систему.
2. При консультации направлять пользователя к нужному вузу. Контекст конкретной программы должен быть видимым и сбрасываться после ухода.
3. Дать доступ ко всем результатам подбора, отдельно от записей с неподтверждёнными условиями.
4. Предупреждать об отсутствии подтверждённых записей в каталоге до завершения анкеты; не утверждать, что таких программ нет в России.
5. Переносить в AI только явно подтверждённые условия. Свободный текст анкеты автоматически не передавать.
6. На телефоне показывать сравнение блоками по критериям; названия программ и неизвестные значения сохранять в каждом блоке.
7. Увеличить области кнопок-иконок до 44 px, исправить контраст и дать режиму крупного текста действительно увеличивать меню.
8. Сохранить постоянные поле ввода и журнал AI, отделить сетевую ошибку от отсутствия подключения.

## Внесённые изменения

| Проблема | Реализация |
|---|---|
| Программа другого вуза открывала прежде всего контакты РГСУ | Консультация начинается с выбранной программы, её организации и официального источника. Контакты РГСУ показываются в подходящем контексте. Есть выбор конкретной программы, сравнения и избранного. |
| Из полного результата были доступны лишь первые шесть записей | Подбор сохраняет полную отсортированную выдачу и показывает «показано / всего». Основные и требующие уточнения варианты догружаются отдельно. |
| Не все причины неопределённости были видимы | Карточки требующих уточнения вариантов показывают все неподтверждённые условия. |
| Округа и полностью онлайн-формат могли приводить к заведомо пустому каталогу | Селекторы отмечают отсутствие данных; отдельное пояснение сообщает об охвате каталога, сохраняя выбранное условие. |
| Условия вводились заново в AI | Кнопка «Обсудить с AI» переносит только структурированные условия. Пользователь видит их и подтверждает применение. Пустые значения показываются как снятие ограничения. |
| Направление подготовки выглядело как конкретная программа | Добавлены метка «Направление» на карточке и тип записи в сравнении. |
| Карточки сжимались сильнее содержимого | Сетка учитывает минимальную ширину карточки; действия могут переноситься. |
| Мобильное сравнение требовало неочевидной горизонтальной прокрутки | Создано представление по критериям с полным названием каждой программы и её значением. Фильтр различий использует тот же набор данных, что и таблица. При печати остаётся одна таблица. |
| Крупный текст компенсировался уменьшением шрифта меню | Компенсирующее уменьшение удалено. Крупное мобильное меню занимает две строки; его фактическая высота учитывается в отступах, уведомлениях и панели сравнения. |
| Низкий контраст отдельных подписей и кнопки сравнения | Исправлены текстовые цвета и пары фон/текст, включая режим высокого контраста. Области иконок приведены к 44 px. |
| Удаление разрушало активный элемент | Фокус переходит к соседнему видимому действию или резервному элементу. Отмена возвращает его к восстановленной программе. |
| Отмена из модального окна была недоступна на фоне | Уведомление располагается внутри открытого диалога. Таймер приостанавливается при фокусе; после отмены фокус возвращается к инициатору. |
| AI пересоздавал поле ввода и весь журнал при обновлениях | Поле и журнал сохраняются. Новые сообщения добавляются адресно, ответ не перехватывает фокус. Содержимое подтверждений и карточек обновляется только при изменении. |
| Старые асинхронные операции могли менять новое состояние | Проверки подключения защищены идентификатором представления и контроллером запроса. Применение импортированного профиля запрещено во время ответа на старые условия. |
| Любая ошибка проверки AI выглядела как отсутствие настройки | Разделены проверка, готовность, отсутствие подключения, временная ошибка и статическая версия. Сообщение сохраняется для повтора. |

## Проверки и границы выводов

Успешно выполнены **63 автоматические проверки**, включая ограничения подбора, независимость коллекций, полную выдачу, контекст консультации, состав переносимого профиля, статический режим и отмену устаревшего запроса.

Дополнительно проверены синтаксис JavaScript, граф клиентских модулей, разбор CSS и сборка GitHub Pages. AI-провайдер в тестах заменён контролируемыми ответами; настоящий ключ не подключён.

Экспертный аудит основан на исходниках, данных и небраузерных проверках. Визуальное отображение на устройствах, реальный клавиатурный сценарий, скринридер и ответы действующей модели не проверялись. Поэтому документ не присваивает интерфейсу формальную оценку «10/10» и не заявляет полное соответствие WCAG.

Для следующей проверки на устройствах: ширины 320, 390, 768, 800, 1024 и 1440 px; обычный и крупный текст; сохранение и отмена в диалоге; удаление последней программы; сравнение трёх вариантов; поздний ответ AI после смены раздела.

## Размещение на GitHub

Подготовлены отдельная статическая сборка `dist/pages` и workflow автоматической публикации. В публикуемый каталог не входят сервер, секреты и идентификатор существующего Sites-проекта. Ссылки на ресурсы относительные и подходят для адреса проекта GitHub Pages.

GitHub Pages размещает статические файлы и не исполняет сервер AI. Поэтому диалог требует отдельного серверного подключения; пошаговый подбор, поиск, избранное и сравнение работают локально. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

Для workflow Pages нужно включить публикацию из GitHub Actions в настройках нового репозитория. Первичное включение через `configure-pages` не выполняется обычным `GITHUB_TOKEN`. [Параметры официального действия configure-pages](https://github.com/actions/configure-pages/blob/main/action.yml).

Создание нового репозитория и фактическая публикация на GitHub зависят от завершения входа владельца. На момент подготовки отчёта публикация GitHub ещё не подтверждена.
